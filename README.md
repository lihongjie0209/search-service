# search-service

搜索投影的 completed Inbox 记录默认保留 14 天（大于 JetStream 默认回放窗口），服务按 500 条有界批次清理。失败或处理中记录不会删除，确保重投与诊断边界不被破坏。

Tenant-scoped global search projection for the microservice platform. The service stores no source-of-truth business records: owning services publish versioned search-document events through NATS JetStream, and this service maintains an OpenSearch projection.

## Interfaces

Frontend-facing HTTP endpoints use POST + JSON and the common `{code,message,body,request_id}` envelope:

- `/api/v1/search/query` — full-text query, filters, sorting, pagination, highlights and facets
- `/api/v1/search/suggest` — type-ahead suggestions with the same application filters as full search
- `/api/v1/search/get` — retrieve one visible projection document
- `/api/v1/version`, `/live`, `/ready`, `/swagger/index.html`

Service-to-service operations use the central `platform-protos` contract `platform.search.v1.SearchService`:

- `Search`, `Suggest`, `GetDocument`
- `BatchUpsertDocuments`, `BatchDeleteDocuments` for controlled rebuild/backfill
- normal online indexing uses `SearchDocumentUpsertedEvent` and `SearchDocumentDeletedEvent`

Do not add local `.proto` files. Contracts are versioned in `contracts/platform-protos` and consumed as a pinned Go module.

## Security model

Production JWTs are verified from identity-service JWKS with issuer and `search-service` audience checks. The shared principal carries user, tenant and membership identities. A request whose JWT tenant differs from `tenant_id` is rejected.

Search visibility tokens are generated by backend owners, never by a page request. Supported tokens are `tenant:<id>:*`, `user:<id>`, `membership:<id>`, `role:<id>` and `service-account:<id>`. Role tokens are resolved server-side from authorization-service. Documents carrying `permission_code` cannot use tenant-wide visibility.

`Search` and `Suggest` verify every requested application through application-service before querying OpenSearch. `GetDocument` verifies the application recorded on the returned projection, so a caller cannot bypass an application grant by guessing a document ID. Documents with an empty application remain tenant/platform-level projections.

Batch index RPCs should be protected with a service-account JWT or a configured PSK wildcard. OpenSearch failures and authorization dependency failures fail closed.

## Projection consistency

- NATS JetStream provides durable delivery, explicit acknowledgement, bounded retry and dead-letter handling through the shared event-bus SDK.
- `search_event_inbox` provides service-local consumer idempotency.
- OpenSearch writes use `version_type=external_gte` with `source_version`, so delayed or replayed events cannot overwrite a newer document.
- The canonical OpenSearch ID is derived as `tenant:source_service:document_type:source_id`; callers cannot select an arbitrary collision key.
- PostgreSQL is the default Inbox database under the `search` schema. MySQL and Kingbase migrations are also maintained.

## Development

```bash
make dev-up
make dev-logs
make dev-down
```

The Compose stack starts PostgreSQL, MySQL, Redis, NATS JetStream, OpenSearch, migrations and the API. It intentionally excludes Prometheus, Grafana, Jaeger and the OpenTelemetry Collector.

Environment profiles load in Spring Boot style: `config.yaml`, then `config-{environment}.yaml`, then `APP_*` environment variables. `-env` has the highest priority. Secrets must not be committed.

Important production variables include:

```text
APP_DATABASE_DSN
APP_MIGRATION_DATABASE_URL
APP_REDIS_ADDRESS
APP_EVENT_BUS_URLS
APP_OPENSEARCH_ADDRESSES
APP_AUTH_JWKS_URL
APP_AUTH_ISSUER
APP_AUTH_AUDIENCE
APP_OUTBOUND_GRPC_AUTHORIZATION_TARGET
APP_OUTBOUND_GRPC_APPLICATION_TARGET
```

## Migrations

Every table contains audit timestamps/actors and an optimistic-lock `version`. The migration history table is service-specific (`search_schema_migrations`) so multiple services can share one database safely.

```bash
make migrate-up
make migrate-down
```

Startup migration is enabled in Compose and production deployment profiles. PostgreSQL and Kingbase support schema isolation; production schema creation remains a platform/DBA responsibility.

## Verification and release

```bash
go test ./...
go test -race ./...
make test-integration   # Docker: PostgreSQL, MySQL, Redis, NATS and OpenSearch
make swagger-check
golangci-lint run ./...
go vet ./...
```

CI runs unit/race, lint, Swagger drift, Kubernetes validation and Testcontainers integration separately. Tagged builds publish multi-architecture images with version, Git commit, build time, SBOM and provenance.

Build metadata is available from `api -version` and `/api/v1/version`:

```bash
make build
./bin/api -version
```
